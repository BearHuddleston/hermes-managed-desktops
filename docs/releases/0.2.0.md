# v0.2.0 — experimental independent desktops

Managed Desktops now provides a standalone Linux/KVM CLI with optional native
Hermes integration. No unpublished Hermes core patches are required.

## Changes from 0.1.0

- Manage and recover guests through `hermes-managed-desktops` or
  `python -m managed_desktops`, without installing Hermes.
- Store VM disks, guest credentials and ownership metadata outside Hermes profiles.
- Require explicit profile scope for agent work and deliberate `--global` operator
  scope for recovery. Bindings identify physical profile directories, not copied tokens.
- Preserve opaque guest arguments through the standalone CLI. Native `exec`, `app`
  and `cua` refuse with guidance instead of accepting arguments altered by core parsing.
- Keep explicit VM/screen targeting, persistent two-work-area guests, transfers,
  captures, recording and loopback viewers.

## Compatibility and evidence

Python 3.11–3.13 is supported. Read `BUILD_INFO.json` for the exact source commit
and pinned Hermes revision associated with these artifacts, and inspect the
matching CI run. The 0.2.0 runtime also passed a local compatibility audit against
Hermes `8aa219ef60ae16bd130e4775a1513e122880654e`: no deprecated import hits,
134 plugin tests passed with compatibility warnings treated as errors, and real
directory/wheel integration and standalone installation checks passed on Python 3.11.

The earlier implementation acceptance exercised two-screen GUI work, profile
lifecycle boundaries, recovery, guest persistence, networking and cleanup. CI does
not provision KVM guests, and packaging a release does not repeat that acceptance.

## Limits and migration

This is experimental software, not a malware sandbox. Native plugins have host-user
privileges. VM runtime requires Linux x86_64/KVM, QEMU, OVMF, cloud-image-utils,
OpenSSH and a user systemd session. Two screens share one guest account/filesystem;
NAT can reach the host or LAN unless separately restricted.

Deleting/renaming a Hermes profile or disabling/uninstalling the plugin does not
stop or delete external guests. Recover them deliberately with the standalone
operator CLI. In-place profile restores preserving directory identity retain
access; already-open operations are not synchronously revoked.

Existing 0.1.0 resources are not automatically migrated. Retain the old version and
its prerequisite harness for their cleanup; do not delete disks to bypass a binding
refusal. Keep standalone recovery installed outside Hermes profiles.

There is no PyPI publication. The attached wheel and source archive have SHA-256
checksums; provenance is unsigned metadata, not a signed attestation.
